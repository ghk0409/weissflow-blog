"무거운 가상환경 진입과 의존성 설치 없이, 0.05초 만에 실행되는 단일 CLI와 내 코드 변경 영향을 즉시 추적하는 정적 분석기를 만들다."

1. Hook & Pain Point: 개발자 도구가 무거워지면 생기는 비극

프로젝트 규모가 커지고 18개의 마이크로서비스가 생기면서 일상적인 개발 루틴에 병목이 생기기 시작했습니다.

1. 가상환경(venv) 스위칭 피로:

  • 지식정원 웹을 확인하려면 apps/mcp-travel/.venv를 켜야 하고,
  • 디스코드 봇을 보려면 apps/discord-bot/.venv로 전환해야 했습니다.
  • Click, Typer, Rich 같은 무거운 CLI 라이브러리를 설치하다 보면 pip install만 수분이 걸립니다.

    • 2. "이 함수 고치면 어디가 깨질까?"의 공포:

  • core/sensors/base.py의 메서드 파라미터 하나를 수정할 때마다, 18개 마이크로서비스 중 어느 파일이 영향을 받는지 알기 어려웠습니다.
  • 매번 전체 테스트를 다 돌리거나 grep으로 일일이 검색하는 것은 비효율적이었습니다.

이 두 가지 고민을 해결한 것이 바로 ADR 0046: Zero-Dependency Unified Terminal CLI와 ADR 0047: AST Code Impact Analyzer입니다.

3. Deep Dive Code: AST(추상 구문 트리)로 코드 관계 지도 그리기

Python의 ast 표준 모듈은 파이썬 코드를 실행하지 않고도 문법 구조를 순수하게 분해할 수 있는 강력한 도구입니다.

① 모듈 간 Import 관계를 추적하는 AST 방문자 (NodeVisitor)

python
# tools/impact_analyzer.py
import ast
from pathlib import Path
from typing import Set, Dict

class ImportDependencyVisitor(ast.NodeVisitor):
    """파일 내 모든 import 문(import a, from a import b)을 추출하는 방문자"""
    
    def __init__(self, current_module: str):
        self.current_module = current_module
        self.dependencies: Set[str] = set()

    def visit_Import(self, node: ast.Import):
        for alias in node.names:
            self.dependencies.add(alias.name)
        self.generic_visit(node)

    def visit_ImportFrom(self, node: ast.ImportFrom):
        if node.module:
            self.dependencies.add(node.module)
        self.generic_visit(node)

def build_project_dependency_graph(root_dir: Path) -> Dict[str, Set[str]]:
    """프로젝트 전체를 스캔하여 '누가 누구를 참조하는가'의 역방향 그래프 생성"""
    reverse_deps: Dict[str, Set[str]] = {}

    for py_file in root_dir.glob("**/*.py"):
        try:
            tree = ast.parse(py_file.read_text(encoding="utf-8"), filename=str(py_file))
            visitor = ImportDependencyVisitor(current_module=py_file.stem)
            visitor.visit(tree)

            for dep in visitor.dependencies:
                if dep not in reverse_deps:
                    reverse_deps[dep] = set()
                reverse_deps[dep].add(str(py_file))
        except (SyntaxError, UnicodeDecodeError):
            continue  # 파싱 불가한 파일은 무시

    return reverse_deps

② 함수 및 클래스 호출 영향도 추적

단순히 파일 레벨의 import뿐 아니라, 특정 함수(예: fetch_market_ticker)를 수정한 경우 해당 함수를 호출하고 있는 호출자(Caller) 노드까지 AST의 ast.Call 노드를 탐색하여 정확히 짚어냅니다.

python
class CallReferenceVisitor(ast.NodeVisitor):
    """특정 함수명이 실제로 호출된 위치를 AST 레벨에서 찾아냄"""
    def __init__(self, target_function: str):
        self.target = target_function
        self.calls_found = []

    def visit_Call(self, node: ast.Call):
        func_name = None
        if isinstance(node.func, ast.Name):
            func_name = node.func.id
        elif isinstance(node.func, ast.Attribute):
            func_name = node.func.attr
            
        if func_name == self.target:
            self.calls_found.append(node.lineno)
        self.generic_visit(node)

4. Troubles & Lessons: 정적 분석기를 만들며 배운 점들

트러블슈팅: 동적 임포트(Dynamic Import)와 상대 경로(Relative Import)

Python에서는 from .base import Sensor 같은 상대 경로 임포트나, importlib.import_module("foo") 같은 런타임 동적 임포트가 종종 사용됩니다.

  • 해결책:

    • 1. 상대 경로(node.level > 0)의 경우 현재 파일의 디렉터리 깊이(Parent Directory)를 계산하여 절대 모듈 패키지 명칭으로 정규화(Canonicalization)했습니다.

    2. importlib을 사용한 동적 임포트는 정적 분석의 한계로 인지하고, AST 탐색 중 문자열 인자(ast.Constant)를 감지하면 '잠재적 영향도(Potential Dependency)' 플래그를 달아 경고를 띄우도록 보완했습니다.

순수 파이썬(Stdlib Only)의 경이로운 장점

외부 라이브러리를 단 하나도 쓰지 않고 argparse, ast, json, subprocess, urllib만으로 구현하니:

  • 어떤 파이썬 가상환경에서도(심지어 시스템 기본 Python에서도) 즉시 실행됩니다.
  • 가상환경 로딩 지연이 없어 터미널 명령 체감 반응 속도가 즉각적(Instantaneous, < 50ms)입니다.
  • Docker 컨테이너나 원격 서버 CI/CD 파이프라인에 주입할 때 의존성 설치 과정이 완전히 생략됩니다.

5. Takeaways & Next Steps

1. 도구는 가벼워야 매일 쓰게 됩니다. 화려한 서드파티 CLI 프레임워크보다 표준 라이브러리로 깎은 0.05초짜리 도구가 생산성을 극대화합니다.

2. 코드 변경의 두려움은 AST 정적 분석으로 해소하세요. 전체 테스트를 하염없이 돌리지 않아도, 내가 수정한 코드가 시스템 어디까지 영향을 주는지 수학적으로 증명할 수 있습니다.

3. 독립 모듈로 분리하세요. WeissFlow의 wf impact는 이제 다른 외부 프로젝트 폴더에서도 복사해 바로 실행할 수 있는 유용한 독립형 유틸리티가 되었습니다.
