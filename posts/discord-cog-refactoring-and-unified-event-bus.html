1. Hook & Pain Point: 거대해진 봇의 공포와 '스파게티 코드'의 역습

WeissFlow가 성장하면서 디스코드 봇은 모든 마이크로서비스의 '총괄 사령탑' 역할을 맡게 되었습니다.

  • 지식정원 AI RAG 질의응답 (/질문)
  • 모닝 브리핑 및 날씨 조회 (/브리핑)
  • 김치프리미엄 및 암호화폐 시세 (/김프, /코인)
  • 가계부 지출 입력 및 구독 관리 (/지출)
  • AI 숏폼 영상 제작 및 큐 모니터링 (/콘텐츠)
  • 원격 데스크톱 Wake-on-LAN 부팅 (/부팅)

하지만 이 모든 기능이 단 하나의 파일(bot.py)에 누적되면서 코드는 어느덧 5,000줄을 돌파했습니다.

더 이상 이 스파게티를 방치할 수 없었습니다. 우리는 봇을 완전히 분해하기로 결정했습니다.

2. Architecture: 8개 마이크로 Cogs와 통합 이벤트 버스 (Unified Event Bus)

우리는 discord.ext.commands.Cog 패턴을 채택하여 기능을 8개의 도메인 단위로 완벽하게 격리하고, 외부 서비스와의 통신은 비동기 통합 이벤트 버스(Pub/Sub)로 디커플링했습니다.

도메인 분리의 핵심 원칙

  • Fault Isolation (결함 격리): 특정 Cog(예: LedgerCog)에서 예외가 터져도 다른 Cog(예: GardenCog)의 슬래시 명령어와 봇 세션은 영향을 받지 않습니다.
  • Zero-Downtime Hot Reload (무중단 핫 리로드): 봇 프로세스를 재시작하지 않고도, 수정된 특정 Cog만 메모리에서 즉시 언로드 후 다시 로드할 수 있습니다 (/reload content).
  • Loose Coupling (느슨한 결합): 외부 마이크로서비스는 디스코드의 채널 ID나 봇 토큰을 몰라도, 이벤트 버스에 정형 이벤트 규격(CONTENT_RENDERED)만 발행하면 디스코드 알림이 자동으로 전송됩니다.

3. Deep Dive Code: 실전 리팩터링 구현체

① 비동기 통합 이벤트 버스 엔진

python
# apps/discord-bot/events.py
import asyncio
from enum import Enum
from typing import Dict, Any, Callable, List

class EventType(str, Enum):
    CONTENT_RENDERED = "CONTENT_RENDERED"
    CONTENT_CANDIDATES = "CONTENT_CANDIDATES"
    GARDEN_TENDED = "GARDEN_TENDED"
    BRIEFING_READY = "BRIEFING_READY"
    SENTINEL_ALERT = "SENTINEL_ALERT"

class UnifiedEventBus:
    """외부 서비스와 디스코드 Cog 간의 결합도를 끊어주는 비동기 이벤트 버스"""
    
    def __init__(self):
        self._subscribers: Dict[EventType, List[Callable[[Dict[str, Any]], Any]]] = {
            e: [] for e in EventType
        }

    def subscribe(self, event_type: EventType, callback: Callable[[Dict[str, Any]], Any]):
        self._subscribers[event_type].append(callback)

    async def emit(self, event_type: EventType, payload: Dict[str, Any]):
        """모든 구독자에게 비차단(Non-blocking) 비동기 전파"""
        callbacks = self._subscribers.get(event_type, [])
        tasks = [asyncio.create_task(cb(payload)) for cb in callbacks]
        if tasks:
            await asyncio.gather(*tasks, return_exceptions=True)

# 전역 싱글톤 이벤트 버스 인스턴스
event_bus = UnifiedEventBus()

② 이벤트에 반응하는 ContentStudioCog 구현

python
# apps/discord-bot/cogs/content_cog.py
import discord
from discord.ext import commands
from apps.discord-bot.events import event_bus, EventType

class ContentStudioCog(commands.Cog):
    """비용 0원 숏폼 콘텐츠 스튜디오 연동 전담 Cog"""
    
    def __init__(self, bot: commands.Bot, notify_channel_id: int):
        self.bot = bot
        self.notify_channel_id = notify_channel_id
        # 이벤트 버스 구독 등록
        event_bus.subscribe(EventType.CONTENT_RENDERED, self.on_content_rendered)

    async def on_content_rendered(self, payload: dict):
        """영상 렌더링 완료 이벤트 수신 시 자동으로 프리뷰 비디오 카드 전송"""
        channel = self.bot.get_channel(self.notify_channel_id)
        if not channel:
            return

        embed = discord.Embed(
            title="🎬 새 숏폼 영상 렌더링 완료!",
            description=f"**주제**: {payload.get('topic')}\n**소요시간**: {payload.get('render_time_sec')}초",
            color=0x10b981
        )
        embed.add_field(name="비디오 파일", value=payload.get('video_path'), inline=False)
        embed.set_footer(text="WeissFlow Autonomous Studio Engine")

        view = PublishApprovalView(video_id=payload.get('video_id'))
        await channel.send(embed=embed, view=view)

async def setup(bot: commands.Bot):
    await bot.add_cog(ContentStudioCog(bot, notify_channel_id=123456789))

③ 동적 Cog 디스커버리 로더 (`bot.py`)

기존 5,000줄에 달하던 bot.py는 이제 단 80줄의 초경량 진입점 파일로 다이어트되었습니다.

python
# apps/discord-bot/bot.py (리팩터링 후)
import asyncio
from pathlib import Path
import discord
from discord.ext import commands

bot = commands.Bot(command_prefix="!", intents=discord.Intents.all())

COGS_DIR = Path(__file__).parent / "cogs"

async def load_all_cogs():
    """cogs 디렉터리 내의 모든 *_cog.py 파일을 자동으로 찾아 로드"""
    for file in COGS_DIR.glob("*_cog.py"):
        cog_module = f"apps.discord-bot.cogs.{file.stem}"
        await bot.load_extension(cog_module)
        print(f"✅ Loaded Cog: {file.stem}")

@bot.event
async def on_ready():
    print(f"🚀 WeissFlow Unified Bot is ready as {bot.user}!")
    await bot.tree.sync()  # 슬래시 명령어 전역 동기화

async def main():
    async with bot:
        await load_all_cogs()
        await bot.start(TOKEN)

if __name__ == "__main__":
    asyncio.run(main())

4. Troubles & Lessons: 리팩터링의 대원칙

트러블슈팅 1: "리팩터링하면서 기존 슬래시 명령어가 깨지면 어쩌지?"

대규모 리팩터링에서 가장 두려운 것은 '기존 기능의 파괴(Regression)'입니다.

우리는 먼저 28개의 Discord Cog 단위 테스트 슈트를 구축하여, 8개 Cog의 모든 명령어 응답과 이벤트 버스 디스패치가 100% 모킹 환경에서 통과하는 것을 사전에 검증했습니다. 그 결과 실제 운영 환경에 배포했을 때 단 하나의 슬래시 명령어 유실 없이 완벽한 무중단 마이그레이션에 성공했습니다.

트러블슈팅 2: 순환 참조(Circular Dependency) 방지

Cog에서 다른 Cog의 상태를 조회하거나 봇 인스턴스를 주고받을 때 흔히 순환 참조 오류가 발생합니다.

우리는 UnifiedEventBus를 완전한 순수 데이터 브로커로 분리하여 어떤 Cog도 다른 Cog의 모듈을 직접 import하지 않도록 아키텍처 규칙을 엄격히 강제했습니다.
